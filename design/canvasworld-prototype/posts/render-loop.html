Rendering nine thousand points at sixty frames a second

Jul 2026 · 5 min read

The full Lorenz stage holds a 9,000-sample buffer. Drawing each sample as its own path would stall the main thread. The trick is batching: stroke short polylines, age their opacity by index, and never rebuild the trajectory unless a parameter actually changes.

Precompute once

Integration happens offline into typed arrays. The rAF loop only advances a drawnCount cursor and redraws. Changing σ / ρ / β recomputes the buffer; scrubbing does not. 

for (start = 0; start < drawn - 1; start += chunk) {
  beginPath()
  // lineTo projected samples in [start, end)
  strokeStyle = rgba(…, ageAlpha)
  stroke()
}

Why chunks matter

One giant path forces the browser to rebuild a huge stroke every frame. Chunks of ~50 segments keep GPU work predictable and let us tint early vs late trajectory differently without per-vertex shaders.

Budget Target: stay under ~8ms of canvas work on a mid laptop at 1× speed with the default 9k buffer. The mini player here uses a smaller buffer so the FPS chip stays honest on weaker machines.
