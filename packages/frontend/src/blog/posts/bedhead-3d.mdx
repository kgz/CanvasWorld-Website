## Three discrete steps

Still no `dt`. Each sample is the next point on the map:

<BlockMath math={'x_{n+1} = \\sin(x y / b)\\, y + \\cos(a x - y)'} />
<BlockMath math={'y_{n+1} = x + \\sin(y)/b'} />
<BlockMath math={'z_{n+1} = y + \\cos(y x)/b'} />

The first two lines are the 2D Bedhead rule. The third was added for depth: `z` leans on the current `y` and the product `yx`, still divided by `b`.

```ts
const next = bedheadAttractor3dTick(x, y, z, a, b)
// store (x, y, z) scaled for the stage camera
```

`b` is a denominator, so the stage floors it away from zero. Extreme samples get clamped so a bad pair does not blow the camera.

## Point cloud, not a butterfly trail

Lorenz and Aizawa integrate rates into a line. Bedhead 3D drops each iterate as a point, like the flat Bedhead cloud, then lets transport `n` decide how far the pile has grown. Change `a` or `b` and the cloud rebuilds from the origin.
